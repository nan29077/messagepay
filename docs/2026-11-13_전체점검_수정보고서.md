## 수정 내역

### 높음

**D-1. 제출된 문서가 서식 수정에 따라 바뀌어 보임** — `documents.ts`, 제출 상세, 공개 작성 화면

  지우거나 이름을 바꾸면 이미 제출된 문서의 값이 사라지거나 다른 이름으로 보였고, 이용자가 동의한
  본문도 바뀌었다. 저장 메시지("제출 당시 내용 그대로 남습니다")와도 맞지 않았다.
- 제출 시점에 항목 정의·서식 이름·본문을 함께 저장한다(`fields_snapshot` / `template_name_snapshot` /
  `body_snapshot`, 마이그레이션 `20261113090000_document_submission_snapshot`, 컬럼 추가만).
- 화면은 `submissionView()` 로 그린다. 스냅숏이 없는 예전 제출 건과 작성 대기 건은 현재 서식으로 그린다.

**F-1. 폼 검증에 실패하면 입력한 내용이 전부 지워짐** — `components/form-dispatch.ts`(신규),
가맹점 `ActionForm`, 관리자 `ActionForm`·`ActionFormWithDetail`, 문서 작성 화면
- React 19 의 `<form action>` 은 제출이 끝나면 결과와 상관없이 비제어 입력칸을 초기화한다.
  상품 등록·서식 등록·약정서 작성처럼 긴 폼에서 서버 검증에 한 번 걸리면 다시 처음부터 써야 했다.
- 공용 폼은 기본 제출을 막고 같은 액션을 트랜잭션으로 직접 호출한다(자동 초기화 없음).
  성공했을 때만 `form.reset()` 해서 "추가" 폼이 비워지는 기존 동작은 유지한다.
- 공개 문서 작성 화면은 회원가입·가맹점 신청 폼과 같은 방식(실패 시 값을 돌려받아 `defaultValue`)으로 고쳤다.

**D-3. 확인 완료 · 작성 링크 재발송의 경쟁 상태** — `studio-documents.ts`
- 확인 완료: 조회 후 update 라 담당자 둘이 동시에 누르면 둘 다 성공했다. 상태 조건부 `updateMany` 로 바꿨다.
- 재발송: 확인과 토큰 교체 사이에 이용자가 제출하면 제출된 문서의 링크를 갈아 끼워, 이용자가 자기
  제출본을 못 보고 불필요한 문자까지 나갔다. `status = DRAFT` 조건으로만 교체한다.

**M-1. MO 번호 동시 배정** — `actions/admin/transactions.ts#assignMoNumber`
- 가맹점 목록 인라인 배정이 생기면서 두 관리자가 같은 번호를 동시에 배정하기 쉬워졌다.
  확인 후 update 라 뒤 요청이 앞 배정을 덮어써 이용자 문자가 다른 가맹점으로 갈 수 있었다.
  조회 당시 상태·가맹점을 조건으로 건 `updateMany` 로 선점하고, 실패하면 다시 시도하라고 알린다.

### 중간

**D-4. 작성 링크 재발송 횟수 제한 없음** — 문서 한 건당 1시간 3회로 제한(`doc-resend`).

**D-5. 파일 서식 주소 검증이 주석과 다름** — `safeFileUrl`
- 주석은 제3자 도메인 링크를 막는다고 했지만 실제로는 모든 https 주소를 받았다.
  자체 업로드 경로(`/api/media/<32hex>.<pdf|docx|doc|hwpx|hwp>`)만 받는다.
- 업로드 API 는 저장소가 S3 여도 `/api/media/` 경로를 돌려준다. 공개 버킷 주소를 그대로 쓰면
  미디어 라우트의 첨부 고정(Content-Disposition)·nosniff 를 거치지 않고 열렸다.
  S3 시절 주소로 저장된 값은 같은 파일이면 자체 경로로 바꿔 저장한다.

**L-1. 제출된 문서 목록이 최근 100건에서 끊김** — 페이지(50건) + 상태 필터(확인 대기·작성 대기·확인 완료).

**S-1. 정산 원장 페이지 범위 밖 요청** — `?page=999` 면 원장이 있는데도 "원장 기록이 없습니다" 가 떴다.
  마지막 페이지로 붙인다. 링크의 `month` 값도 인코딩한다.

**P-1. 파트너 API 로 문서 상품 종류 변경 가능** — `PATCH /products/{id}`, 일괄 동기화

  API 문서(PATCH)에 안내를 추가했다.
